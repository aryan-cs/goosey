# Three months of synthetic Goosey activity

This folder contains the **actual saved development dataset**, not just a seed
recipe. All accounts, events and activity are fictional. It includes the original
90-day simulation and the agent's subsequent test trades and comment.

## Use it as your starting point

From the repository root, with Node.js 20.9+ installed:

```sh
npm ci
npm run db:generate
npm run data:fixture -- import --name shared
npm run data:dev -- serve --name shared
```

Open **http://localhost:8082**. Your newly generated login password and account list
are in `output/development-sandbox/shared/credentials.json`. For example, sign in
as `simulation-trader-01@example.test` using the password from that private file.
The import creates a separate local database; it never overwrites an existing
sandbox or touches `prisma/dev.db`. Choose another `--name` if `shared` exists.

By default, import shifts **every timestamp by the same amount** so the capture
time becomes the present. The three-month history, market start/close/resolution
order, and spacing of all trades remain intact, while active markets still have
time left for testing. To reproduce the exact original UTC dates instead:

```sh
npm run data:fixture -- import --name historical --preserve-dates
```

With preserved dates, markets can already be past their deadlines. Their worker
will close elapsed markets normally. Neither import mode changes prices, amounts,
ownership, executed trades or completed payouts.

| Data | Records |

| Probability snapshots | 2,628 |
| Positions | 264 |
| Journal entries / ledger postings | 2,720 / 8,053 |
| Completed position settlements | 69 |
| Comments / watchlist entries | 110 / 60 |
| Notifications | 2,682 |

There are open, paused, closed, resolved-YES, resolved-NO, voided and draft markets.
The historical prices were generated by executing the real LMSR trading service;
trades, charts, volumes, portfolios and payouts reconcile. This is a development
fixture for the existing backend, not real Kalshi/Polymarket history or Solana
activity. The export intentionally rejects order-book markets until that entire
accounting graph has its own supported fixture format.

## File format and privacy

Each `Model.jsonl` file contains one JSON record per line. Foreign-key IDs preserve
relationships across files. Big integers (including milli-feather amounts) are
decimal **strings**, avoiding JavaScript number rounding. Dates are ISO 8601 UTC
strings; probabilities are integer basis points, where `10000` means 100%.
Empty files represent tables with no records.

`manifest.json` records the capture time, original scenario anchor, seed, schema
fingerprint, table counts and SHA-256 checksums. Import checks the package before
creating a database, then checks its relationships, chronology and accounting.
Use the schema from the same checkout; a schema mismatch requires an updated
export rather than silently guessing how to migrate the data.

There are **no passwords, password hashes, sessions, verification/reset tokens,
invitation credentials, SMTP settings or application secrets** in this folder.
The exporter never selects password hashes. Authentication tables, request caches,
worker state and audit logs are excluded. Journal metadata is replaced with `{}`;
completed settlement lease/claim/error fields are cleared. All exported identities
must match the generated `simulation-*` accounts at `example.test`.
Fresh passwords and secrets are generated locally on import and remain gitignored.

## Continue testing and share an updated snapshot

Agents and developers can log in and use the normal UI or APIs; activity persists
in their local imported sandbox. Stop its server before using the bulk CLI:

```sh
npm run data:dev -- contribute --name shared --count 20
npm run data:dev -- verify --name shared
```

To update this committed dataset from a sandbox:

```sh
npm run data:fixture -- export --name shared
git diff -- fixtures/synthetic/three-months
```

Export reads a consistent database transaction, so the source server may remain
running. Review the changed fictional content before committing; do not put real
people's details or credentials into comments or other free-text fixture fields.
Never commit the private sandbox directory or copy this dataset into production.

See [the development sandbox guide](../../../docs/development-sandbox.md) for
the generator, reset/archive workflow and agent testing conventions.
