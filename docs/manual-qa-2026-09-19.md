# Manual browser QA — September 19, 2026

Three independent testers exercised account access, settings, and market journeys using disposable accounts created through the UI. A fourth pass checked navigation, keyboard behavior, responsive layouts, and visual consistency. These were browser interactions, supplemented by focused regression tests; they were not API-only checks.

## Environment

- Local production build, isolated SQLite database, local SMTP capture, and local HTTPS proxy. No external email delivery or live account mutations.
- Separate browser contexts for account tests; Chrome visual checks at 320, 375/390, 820, and 1440px. Light and dark appearances inspected.
- Browser screenshots retained under ignored `output/playwright/` and temporary auth QA artifacts.

## Defects corrected during QA

- Decimal contract quantities crashed the market page during BigInt conversion. Invalid input now displays an accessible range error and disables review; 13 regression cases cover payout safety and supported boundaries.
- Signup/profile hints and HTML patterns disagreed with server username rules. Both now require letters/numbers at the ends and explain the rule.
- Escape closed the market dropdown while leaving focus on a hidden link. Focus now returns to Markets; tabbing out also closes the dropdown.
- Resizing an open mobile menu to desktop left body scrolling locked. The menu now closes at the desktop breakpoint.
- A narrow-screen override removed auth-card rounding. Cards now retain the shared radius at 320px.
- Same-document verification links with a new token fragment were ignored. The account flow now handles hash changes; retested without reload.
- Password reset revoked sessions but left signed-in navigation visible. The recovery flow now refreshes the server-rendered session state; retested on the final production build.

## Additional finding

Legacy market-maker notifications exposed internal milli-feather units. This was handed to the Dev task, which updated new-notification formatting to feathers. Existing stored notification copy is unchanged; a fresh notification after that final copy change was not manually retested in this pass.

## Scope limits

This is a bounded QA pass, not proof that every possible edge case is covered. Safari, Firefox, real iOS/Android devices, external SMTP delivery, load/concurrency testing, and an approved Hack the North SSO integration were not exercised here. Backend automated suites cover additional authorization, accounting, and concurrency behavior separately.
